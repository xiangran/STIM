## 1. 计划目标和范围

本计划只覆盖嵌入式固件工作，Linux 上位机和硬件设计由对应工程师负责。固件预计涉及：

- 低频可拆卸治疗模块：处方接收与校验、本地按键/显示、波形输出、强度调节、电池与充电、故障保护、独立运行。
- 中频控制单元：载波/包络/断续波形、多通道时序、强度控制、输出监测和安全联锁。
- 充电座或模块管理：模块定址、充电状态、处方下发、版本管理和多模块并发通信。
- 通用能力：Bootloader/IAP、参数存储、校准数据、日志/故障码、看门狗、掉电安全和生产测试接口。

> Linux 主机 UI 不属于固件交付范围；固件仅负责与 UI 相关的接口、状态和错误码。低频可拆卸模块自身的屏幕和按键属于固件范围。

## 2. 排期原则

1. **需求和安全边界先行**：波形范围、最大输出、故障状态和恢复条件在功率级联调前必须评审。
2. **前 6 周不等定制 PCB**：使用开发板、核心板、软件模拟器和 Linux Mock 接口开发架构、状态机、协议和波形时序。
3. **先数字接口，后高压功率级**：新板上电首先验证时钟、调试口、通信、按键、显示和采样，之后才在假负载上启用输出。
4. **低频与中频功率联调错开**：第 9 周优先低频，第 10 周优先中频，减少对示波器、差分探头、假负载和硬件人员的争用。
5. **协议早冻结、上位机晚集中联调**：第 3 周开始 Mock，第 6 周冻结主要字段，第 11—12 周进行实机联调。
6. **第 15 周起原则上不增加新功能**：只允许缺陷修复、测试、文档和发布工作。

### 6.3 测试和证据

- 回归测试、稳定性、时序抖动、Flash/RAM/堆栈和功耗记录。

- 烧录、序列号、硬件版本识别、校准、自检和 EOL 测试接口。
- 升级、升级中断恢复、回退和版本不匹配处置说明。
- 故障日志导出、诊断命令、已知问题和维护交接文档。

## 7. 每个里程碑的通用完成标准

- 对应代码已合入受控分支，可使用记录的工具链重新构建。
- 编译无警告，静态检查无未处理的高风险项。
- ISR 仅进行必要的读取、清除和通知，无阻塞、无未受控动态内存。
- 看门狗、超时、错误返回、输出禁能和安全恢复路径已验证。
- 关键定时、PWM、ADC 同步和中断延迟有逻辑分析仪/示波器证据。
- 需求、测试用例、缺陷和评审记录具有唯一编号并可追溯。
- 高压激励和功率输出只能在经评审的假负载上验证，研发阶段不连接人体。
